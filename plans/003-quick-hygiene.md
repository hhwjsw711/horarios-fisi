## Why this matters

Four small, independent fixes with outsized payoff: (1) type errors currently surface only at `next build` (slowest step) because nothing runs `tsc --noEmit`; (2) `shadcn` ships as a runtime dependency with zero imports; (3) the Clerk webhook swallows every error and returns 400, which tells Clerk NOT to retry, so a transient DB failure silently loses a user sync (the webhook is the auth-to-DB bridge for ~90 production users); (4) `scripts/set-admin-users.ts` falls back to two hardcoded personal emails when run without flags, so an accidental bare run against production reassigns admins.

## Steps

### Step 1: Add a typecheck script and wire it into check + CI

AMENDED 2026-06-11 after first executor run: `tsc --noEmit` fails on the pristine repo with TS2307 `Cannot find module 'bun:test'` in the three test files, because `@types/bun` is not installed. Resolution is part of this step:

1. `bun add -d @types/bun`
2. In `package.json` add `"typecheck": "tsc --noEmit"` and change `check` to `"bun run lint && bun run typecheck && bun run test && bun run build"`. CI already calls `bun run check`; do NOT add a separate CI step.
3. Only if `bun:test` still fails to resolve after installing `@types/bun`, add `"types": ["bun"]` to `compilerOptions` in `tsconfig.json` (tsconfig.json joins the in-scope list for this single line).

**Verify**: `bun run typecheck` exits 0. If OTHER pre-existing type errors surface (unrelated to bun:test), STOP and report the error list (do not fix unrelated type errors in this plan).

### Step 2: Remove the unused shadcn dependency

DROPPED 2026-06-11: the finding was wrong. `shadcn` is consumed from CSS (`@import "shadcn/tailwind.css"` in `src/app/globals.css`); removing it breaks `next build`. Executor verified and reverted. The dependency stays.

### Step 3: Distinguish webhook failure modes

In `src/app/api/webhooks/clerk/route.ts`, split the try/catch so that:
- `verifyWebhook(req)` failure -> log `console.error("clerk webhook verification failed", error)` and return 400 (invalid signature must not be retried).
- Failures after successful verification (DB sync errors) -> log `console.error("clerk webhook processing failed", { type: event.type }, error)` and return 500 so Clerk retries.

Never log the request body or any email/PII; the event type and the error object are enough.

**Verify**: `bun run typecheck` exits 0; `bun run lint` exits 0.

### Step 4: Remove the hardcoded admin fallback

In `scripts/set-admin-users.ts`, when no `--admin-email` flags were passed, print a usage message to stderr (`"Usage: bun run clerk:set-admins -- --admin-email <email> [--admin-email <email>...]"`) and `process.exit(1)`. Delete the hardcoded email array entirely.

**Verify**: `grep -n "raillyhugo@gmail.com\|hpaucar@unmsm.edu.pe" scripts/set-admin-users.ts` returns nothing. Note: README documents an example invocation with explicit flags, which still works; no README change needed.
